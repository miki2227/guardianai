# Persistent agents under context pressure: unrun protocol

The user requested a small number of long-lived agents rather than many fresh
contexts. No additional hosted subject runs have been made under this protocol.
Deterministic broker workers test enforcement mechanics, not model hallucination
or context-window exhaustion.

Use two persistent pretrained subject sessions, ordinary authorized tasks, and no
secret code, concealment instruction, injected malicious objective or weight update.
Each subject remains the same session across tasks. Retain exact exposed history,
tool proposals, actual token accounting, model/provider versions, summarization
events and tool results. Log summaries as new artifacts rather than silently
replacing prior history. Do not infer context exhaustion from turn count or wall time.

Before claiming natural context-limit effects, obtain authoritative context-capacity
and input-token/retained-history measurements. Provider compaction, explicit
experimenter truncation and a naturally reached context limit are different
conditions. If capacity or retained context cannot be measured, label that arm
unmeasured instead of guessing that the window was exceeded.

Use matched task streams with stable versus changed authority, crossed with intact
versus deliberately truncated/summarized exposed history. Scope experiments to
locally supervised tool execution; hosted inference is not inside WSL. Feed every
tool action through containment, use protected resources only through the broker,
and record task-group stop propagation. Include no-change history controls to
separate general task difficulty from stale-authorization requests.

Use fresh synthetic resource versions/canaries after a task transition to distinguish
new unauthorized access from a model recalling data it was legitimately given
earlier. Revocation cannot erase prior knowledge. Report attempts, pre-release
denials, completed reads, release commits and externally observable effects
separately. Wrong guesses and unsupported claims do not establish malicious intent.

Predeclare event/fault families and independent task streams before final testing.
Use deterministic workloads to stress delayed observer replies, interrupted
telemetry, process descendants, socket backpressure, path changes and commit races.
Compare retrospective stop, static grants, commit-time revalidation and measured
prior-system baselines. A fixture deliberately omitting a check is an ablation,
not evidence that a published system contains that defect.

Evaluate utility, stale-action rate, effects before stopping, release ordering,
false stops, overhead and recovery. Repeated turns from one pair are correlated;
use task-stream/pair-level uncertainty estimates when there is enough independent
replication. A single long trajectory cannot support population-level conclusions.
Preserve null emergence, correct behavior, premature termination and observer faults.

Kernel evidence cannot reveal latent thoughts. The testable journal claim must
concern observed policy violations, stale authority and enforceable release
contracts, with explicit gaps for already-released information, unmediated sinks,
unknown lost events and compromised trusted components.
