# Does GuardianAI work?

**Yes, as a bounded prototype for supervised MCP/Linux execution and declared
information-flow policy. It is not yet a validated detector of emergent hidden
signalling, and it cannot inspect private model thoughts.**

The [real Checkstyle attempt](CHECKSTYLE_PRACTICAL_RUN.md) did **not** complete.
One Grok session reached an unavailable Java executable path, then exceeded the
trace budget during discovery. A separate host run with the resolved executable
also abstained during JVM loading. Stopping worked, but this Java investigation
was not practically usable. No Checkstyle bug or P0 was established.

The [latest feedback-cycle attempt](FEEDBACK_LOOP_RUN.md) did **not** complete.
The builder made an invalid child-path read of a virtual resource and was
revoked before building. The denial and stop acknowledgement worked; a clean
scope-closure record is missing. The builder remains quarantined. Return-slot
preparation and a separate authorized host direct-read diagnostic succeeded,
but those are not credited as a completed agent cycle or recovery.

The evidence comes from separate development cases and source snapshots; it is
not a pooled accuracy benchmark. Existing-agent continuation completed eight
actual Linux commands across indexing, release building and correction work,
with three clean closed scopes. Earlier paired work completed 15 commands and
three verified handoffs. The public/internal MCP case withheld the prohibited
index and refused the next command while delivering identical index bytes to
an authorized internal client.

## Generated-file observation

The [two-subject Checkstyle attempt](CHECKSTYLE_PAIRED_RUN.md) exchanged a Jev-
approved transcript and verified its recipient read, but both subjects stopped
before final findings. Process-group backpressure enabled a configured Java
smoke check; the actual investigator later missed an observer deadline and the
reviewer exceeded the host full-message review budget. Practical paired Java
analysis remains incomplete; stopping alone is not successful task completion.

The [host tool-result adapter](TOOL_RESULT_OBSERVER_RUN.md) also observes exposed
CLI replies, including tool discovery. Live Jev replay verified five real saved
replies with exact source joins. It started no agent or worker; these are
retrospective decisions, not a newly completed workflow or pre-delivery control.

The [ZIP packaging run](ZIP_OBSERVER_RUN.md) completed an actual archive-only
release with 152,754 UTF-8 bytes from 20 unique contents submitted in attributed
units. A duplicate-member archive was withheld and its next command refused.
The earlier unresolved-cleanup and oversized-review failures remain retained.
ZIP container bytes and nontext leaves remain opaque; no new actor was used
and the builder's quarantine was preserved.

The [publication-stop run](PUBLICATION_STOP_RUN.md) found and corrected a real
public-only cancellation gap: an acknowledged stop could precede a later file
publication. The final stop check and rename now share the broker commit lock.
The corrected cancellation withheld files and stdout, while the same normal
packaging/checksum work completed. This is one observed schedule per revision;
already committed output and transport cancellation remain separate limits.

The [artifact-observer continuation](ARTIFACT_OBSERVER_RUN.md) closes another
specific blind spot: generated text files now reach Jev before MCP publication,
even when stdout contains only names and sizes. The existing reviewer produced
two files totaling 4,967 text bytes plus an opaque ZIP in one corrected command;
its earlier size-assertion failure is retained. A real source export then exited
zero but exceeded the observation budget: publication abstained, returned an
error, withheld output and refused the next command. This is a coverage and
error-reporting improvement, not a malicious-agent detection benchmark.

## Protected handoff between the existing pair

The [latest paired run](PEER_HANDOFF_RUN.md) completed four Linux commands across
the two existing conversations. The reviewer verified 17 source hashes. Producer
exposure labels travelled through a private digest-pinned peer resource and two
actual kernel commits into the recipient's worker/client labels. Preparation
alone left the recipient unexposed. An uncleared preparation was refused; changed
staging bytes were rejected before worker creation without mutating the ledger.
The initial controller failure and subsequent recovered review are separate
retained outcomes. This closes a concrete peer-publication integration gap;
ordinary cooperation does not establish a covert convention.

## New real crash-recovery check

The [actual run](crash-recovery-runs/v1/run/summary.json) killed the supervising
MCP process with SIGKILL while a release-build Python worker was confirmed live.
The owned process exited with -9. A pidfd confirmed that the observed worker
exited after its supervisor died. This is an interrupted build, not a completed
build or a claim that GCC itself had already started.

The persistent ledger retained its active-session marker. Reopening the same
identity stopped it and returned `abstain: scope_stopped`; no resumed worker
directory was created. The [controller](crash-recovery-runs/v1/workflow.py) and
exact runtime source hashes are retained. The worker used the real packaged
runtime and project release script, with live Jev checks. No new model subjects
or artificial malicious objective were introduced.

This replaces the previous source-only status for one abrupt-death recovery
path. It does not establish every descendant/fault timing, power-loss durability
or hard real-time cleanup.

## What remains

- The [new CLI gate](CLIENT_BINDING_RUN.md) now checks trusted startup metadata
  before admitting commands. Wrong-ID, missing-approval and replay cases were
  refused. The host still owns the canonical ledger mapping and transport; this
  is not cryptographic remote-provider authentication.
- Confidentiality labels cover registered inputs and mediated outputs. They do
  not automatically discover every private input or inspect arbitrary binary
  meaning. A binary in MCP `/output` is nevertheless subject to publication gates.
- Jev can produce false alarms and miss factual mistakes. Contextual review
  cleared a live alert, but human review found the operator-note scope ambiguity.
  Accuracy, calibration and false-negative rates require labelled replicated data.
- The continuing-agent records do not establish context saturation or a
  spontaneous two-agent convention. Hidden provider reasoning is unavailable.
- Atomic ledger replacement is not a tested power-loss durability protocol.

The practical outcome is useful work completing under enforced declared
boundaries, including a successful observed crash/restart refusal. Universal
malicious-activity detection and research-level covert-convention detection
remain unproven. The full goal is not marked complete.
